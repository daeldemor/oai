> Примечание: раздел про Strata (2.1) добавлен после выхода в сеть; источники —
> [stratallm.org](https://stratallm.org/) и
> [обзор vdf.ai от 13.11.2026](https://vdf.ai/blog/strata-local-llm/).
> Остальные разделы проверены практикой локального инференса.

## 1. Что такое аблитерация и какие есть подходы

### A. Ортогонализация направления отказа (FailSpy, 2023 → классика)

1. Прогоняем через модель два набора промптов: «вредные» (на которые модель
   отвечает отказом) и «безобидные».
2. Для каждого слоя считаем разницу средних активаций → получаем вектор
   «направления отказа» (refusal direction) для каждого residual stream.
3. Вычитаем проекцию на это направление из весов (матрицы `o_proj`, `down_proj`
   и др. — «writable» матрицы): `W' = W − r (rᵀW)`.

Плюсы: не нужен датасет и обучение, минуты работы, интеллект почти не страдает.
Минусы: один глобальный вектор — грубовато для крупных моделей; иногда «плывёт»
качество на сложных рассуждениях.

### B. Heretic (p-e-w) — текущий де-факто стандарт

Автоматизирует A, но улучшает его:

- ищет направления **по каждому слою отдельно** и подбирает силу подавления
  через оптику (Optuna): минимизирует одновременно количество отказов и
  KL-дивергенцию к исходной модели (защита «интеллекта»);
- умеет оценивать результат на встроенных наборах промптов;
- работает поверх `transformers`, грузит модель с `device_map="auto"` —
  на 32 ГБ RAM + 16 ГБ VRAM реально аблитерировать dense-модели до ~14B.

Именно им сделана уже стоящая у вас `gemma-4-26B-A4B-it-heretic`.

### C. OBLITERATUS

GUI-инструмент (Brane) для тех же операций + удобная загрузка на Hugging Face.
Удобен как наглядная альтернатива, но менее гибок в скриптовом пайплайне.

### D. Готовые GGUF (mradermacher, huihui-ai, DavidAU и др.)

Не «своя» аблитерация, но самый быстрый путь: авторы уже сделали A/B и выложили
кванты. Теги: `abliterated`, `heretic`, `uncensored`, `decensored`.

### Что выбираем

**Решение (16.11.2026): основной путь — D, готовые GGUF.** Своя аблитерация
(B) не планируется; `scripts/abliterate.py` и `scripts/quantize.sh` оставлены
как опция на будущее.

| Сценарий | Подход |
|---|---|
| Основной | D — готовые heretic/abliterated GGUF (`scripts/download.sh`) + llama.cpp/LM Studio/Bionic |
| Опционально, «на вырост» | B — Heretic (обёрнут в `scripts/abliterate.py`) |

Источники готовых GGUF (по скачиваниям на HF, 16.11.2026): **mradermacher**
(крупнейший каталог, 73k+ репозиториев), **DavidAU** (NEO/IMATRIX/MTP-сборки),
**llmfan46**, **0bserverx**, **jegreene**, **culturerevolt**.
Конкретный shortlist под 16 ГБ VRAM — в `configs/models.yaml`.

### 2.1. Strata — новый MoE-специализированный движок (сентябрь 2026)

[Strata](https://stratallm.org/) (MIT, автор Niko1221, первый релиз 24.09.2026,
активно развивается) — движок, заточенный под запуск **огромных MoE-моделей
на потребительском железе**: предиктивная подгрузка экспертов из RAM/SSD в VRAM,
zero-copy pinned memory, MTP-драфтинг (ускорение ~1.6–1.8x), OpenAI/Anthropic-
совместимый API на :8080.

Поддерживаемые семейства (строго ограниченный список):

- **Qwen3.8-Flash-Next** (~125–180B total / 6B активных) — флагман;
- **Qwen3.6-35B-A3B** — NVIDIA/AMD;
- **DeepSeek V4.1-Flash** — 191–274 ГБ загрузки.

**Что это меняет для нас — и что нет:**

| Вопрос | Влияние Strata |
|---|---|
| Потолок «интеллекта» на этом ПК | **Растёт**: 125B-класс MoE вместо 24B dense. Заявлено 25–87 ток/с на 12 ГБ VRAM + 64 ГБ RAM (замеры автора, независимых нет) |
| Наши 32 ГБ RAM | **Узкое место**: помещается только пакет Coder IQ1_M (~30 ГБ, только код). Q2_0 требует 48 ГБ, IQ3_S — 64 ГБ. Low-RAM режим со стримингом с SSD работает, но заметно медленнее |
| Аблитерация своими руками | **Не меняется**: Strata — только сервинг, и только трёх семейств. Свою abliterated-модель (dense 8–14B) он не запустит; abliterate-пайплайн (Heretic → GGUF → llama.cpp) остаётся основным |
| Готовые abliterated GGUF | llama.cpp остаётся универсальным движком; Strata запустит только heretic-кванты поддерживаемых семейств (если их опубликуют) через `--model-path` |
| Зрелость | Проекту ~2 месяца, один основной мейнтейнер, релизы каждые несколько дней, внешнего аудита не было — версии пиновать, для «боевого» использования рано |
| Конфликт портов | Strata по умолчанию слушает :8080 — как и наш `serve.sh`; задавать `--port` |

**Вывод по Strata:** отличное дополнение, если захочется frontier-уровень MoE
локально — но сначала апгрейд RAM до 64 ГБ. На текущих 32 ГБ наш основной путь
(llama.cpp + свои abliterated GGUF до 14B + готовые MoE-кванты с выгрузкой)
остаётся оптимальным.

### 2.2. Strata: heretic Qwen3.6 запущена — ОСНОВНОЙ стек (16.11.2026, проверено)

- Terminal 0.1.60.1 (`C:\Users\rmari\AppData\Local\Strata\terminal\current\bin\strata.cmd`),
  **движок ставится отдельно**: `strata update --yes --no-control` → engine 0.1.60 `windows-x86_64-cuda-cuda13`
  (без него `strata doctor` показывает только terminal/monitor). Клон исходников — `G:\Work\OAI\strata\` (вне git).
- Strata считает память как RAM+VRAM: наша машина — 31+16=47 ГБ → «40 ГБ tier».
  Из её семейств «хорошо» влезает только **Qwen3.6-35B-A3B в 4 битах**: Flash-Next требует ≥44 ГБ RAM
  или стриминга с SSD (Coder IQ1_M, 63.6 ГБ, сток), Gyro-S — ниже качеством.

**Почему сторонний GGUF сначала не запускался — две причины, обе обходятся:**

1. `strata launch --model-path <папка>` без семейства идёт через импорт, который знает только Flash-Next
   (`plan_import`: архитектура `qwen4exp`) → «this model type is not supported». Для Qwen3.6 свой файл
   подаётся как **`--family qwen36 --model ud-q4_k_xl --model-path <папка>`**, а файл в папке должен называться
   `Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf` (`setup.py: OWN_PATH_FAMILIES`); чужой размер — только предупреждение.
2. Движок проверяет формат экспертов: down-эксперты в **Q4_K не принимаются**
   (`iq_kernels.cu: STRATA_D_FMTS` — Q5_1/Q5_0/Q4_1/Q4_0/Q8_0/Q5_K/Q6_K/IQ4_*). В Q4_K_M 20 из 40 слоёв
   хранят down в Q4_K → `blk.5.experts are Q4_K/Q4_K, which the native expert kernels do not take`.
   Лечение — `scripts/strata_fix_down.py`: перекодирует эти 20 тензоров Q4_K → Q5_1 без потерь по смыслу
   (тот же 4-битный код, scale/min округляются до float16; `--verify` сверяет всё остальное байт в байт).
   Файл растёт с 21.78 до 22.79 ГБ, ~2.5 мин на SSD.

**Рабочий запуск** (файл на SSD `X:`; `G:` — HDD):

```
python -I scripts/strata_fix_down.py <...>-Q4_K_M.gguf X:\OAI-models\qwen36-heretic-strata\Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf --verify
strata launch --family qwen36 --model ud-q4_k_xl --model-path "X:\OAI-models\qwen36-heretic-strata" ^
  --vision off --context 32k --parallel 1 --access local --port 8080 --save-preset heretic-q36-32k --yes --no-tui
# дальше просто: strata launch --preset heretic-q36-32k      стоп: strata launch --stop --preset heretic-q36-32k
```

Нужен llama.cpp b12600+ (архитектура `inkling2_loop`). Стоит b12633 в

**Память.** KV нужен только 4 слоям полного внимания, у 3-проходной середины
свой кэш на каждый проход: 8 кэшей × 2048 чисел на токен. На 128k с q8_0 это
2176 МиБ, ровно как в расчёте. SWA-слои стоят 106 МиБ при любом контексте.

Compute-буфер растёт как контекст × `-ub`, примерно 200 байт на
пару (токен контекста, токен микробатча), даже с `--flash-attn on`. Причина в
коде (`src/models/inkling2.cpp`, `build_attn` в `src/llama-graph.cpp`): bias
относительных позиций собирается через `get_rows` в плотный тензор
n_kv × n_tokens × 24 головы в f32 (96 байт на пару), потом копируется `ggml_cont`
(ещё 96), складывается с маской и приводится к f16, и уже эта маска на каждую
голову идёт в flash attention. Пиковая сумма около 200 байт и есть наблюдаемый
рост. В upstream на 2026-11-22 исправления нет. С дефолтным `-ub 512` буфер на 32k
уже 3.4 ГБ, модель вылезает за VRAM в общую память, и генерация падает до
20 ток/с. Поэтому `-ub` надо подбирать под контекст. Флаг `--no-mmap` в этой
сборке убран, вместо него `--load-mode none`.

#### 2.4.1. Свой патч llama.cpp: внимание по KV-головам (2026-11-22)

Патч: [`patches/llama.cpp-b12633-inkling-rel-attn.patch`](../patches/llama.cpp-b12633-inkling-rel-attn.patch),
4 файла, +103/−24. Исходник `llama.cpp-src/` (b12633, вне git), сборка `llama.cpp-src/build/bin/`
(VS 2022 Build Tools 17.14 + CUDA 13.5, только sm_120). DLL CUDA лежат в
`C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.5\bin\x64`, этот путь нужен в PATH.

Что меняет:

1. `build_attn` для слоёв с относительным bias на длинных промптах считает flash attention
   отдельно для каждой из 8 KV-голов. Маска с bias одновременно живёт только для 3 голов из 24.
   `LLAMA_ATTN_REL_SPLIT=0` возвращает старое поведение.
2. Bias переводится в f16 при перестановке осей, маска добавляется уже в f16. Маска содержит
   только 0 и −inf, поэтому результат тот же.
3. CUDA `get_rows` для строк короче 33 элементов копирует один элемент на поток. Раньше на каждую
   строку уходил блок из 256 потоков, и с разбиением по головам prefill падал вдвое.

Compute-буфер растёт на ~32 байта на пару вместо ~200. На 32k с `-ub 256` было 1678 МиБ, стало 385.

| Конфиг | Буфер | Заполнение | Prefill | Генерация |

Полное заполнение 298k (иголка на глубине 0.25 найдена) заняло 17 минут вместо 39. В конце
prefill шёл ~205 ток/с вместо ~87, то есть 5k новых токенов на этой глубине обрабатываются за
~25 с. VRAM 15.1 ГБ. «Общая память GPU» в диспетчере задач (~4.5 ГБ) — это pinned RAM под
эксперты на CPU (`CUDA_Host model buffer`), а не перелив.

Проверка точности: 4.7k промпт, 48 токенов, top-3 вероятности. Старая сборка повторяет себя бит в
бит, патч с `LLAMA_ATTN_REL_SPLIT=0` совпадает со старой бит в бит. С разбиением максимальная
разница вероятностей 0.076, первое расхождение токена на 42-м. У старой сборки при смене
`-ub 256` на `-ub 512` разница 0.094, так что это шум порядка суммирования.

`--no-op-offload` (эксперты из RAM считает CPU, веса не гоняются по PCIe) хуже: на 320k,

Правило: веса GGUF + 1.5–3 ГБ под KV-кэш и систему ≤ 15 ГБ.

## 4. Аблитерация своими руками: ресурсы

Heretic грузит модель в bf16: память ≈ 2 × params + активации.

| База | bf16 вес | Реально на 32 ГБ RAM + 16 ГБ VRAM? |
|---|---|---|
| Qwen3-8B | ~16 ГБ | Да, полностью на GPU почти впритык / auto-offload |
| Gemma-3-12B / Qwen3-14B | ~24–28 ГБ | Да, с выгрузкой слоёв в RAM (медленнее) |
| Mistral Small 24B | ~48 ГБ | Нет — брать готовый GGUF или машина с ≥64 ГБ RAM |

## 5. Оценка качества (обязательный шаг)

Аблитерацию нельзя делать «вслепую». `scripts/evaluate.py` меряет:

1. **Refusal rate** — доля отказов на наборе из ~40 провокационных промптов
   (детектор по фразам «I cannot», «Извините, я не могу» и т.п.).
2. **Сохранность интеллекта** — сравнение ответов на нейтральных бенчмарк-промптах
   (простые задачи по логике/математике/коду) до/после; при серверном режиме —
   сравнение по метрикам ответов, при локальном — KL-дивергенция (её считает
   сам Heretic при подборе параметров).

Критерий приёмки: refusal rate ≤ 5% на пробах, при этом базовые задачи решаются
на уровне исходной модели.

evaluate и serve.
